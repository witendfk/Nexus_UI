# 删除与迭代计划模板

来源：sanyuan0704/sanyuan-skills `code-review-expert`（适配 OrderOps）。

## 优先级

- [ ] **P0**：立即删除（安全风险、显著成本、阻塞其他工作）
- [ ] **P1**：应尽快删除（死代码、过时文档说明、误导性注释）
- [ ] **P2**：值得做（冗余抽象、无调用方的导出）
- [ ] **P3**：可选（风格性简化）

## 每项删除候选必须给出

1. **删除收益**：减少多少行/多少维护面/消除什么误导
2. **风险评估**：是否有隐藏调用方（grep 证据）、是否在测试/文档中被引用
3. **替代方案**：若不删，如何用注释/重命名降低成本

## OrderOps 迭代时的专项删除项

- 穿刺代码升级为正式实现后，玩具生成源/玩具 Catalog 必须删除或移入测试 fixture（不留双实现）。
- 文档中"目标设计"段落在该能力落地后改写为事实描述，删除过时差距条目（§9 纪律）。
- Nexus tarball 升级后旧的 `tarballs/*.tgz` 删除，避免 overrides 指错版本。
